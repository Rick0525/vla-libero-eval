## 三层定义

| 层 | 回答的问题 | 典型修法 |
|---|---|---|
| 感知 | 看对了吗（语言 grounding、物体识别、几何/深度理解） | 视觉编码器、相机视角、指令表述 |
| 规划 | 认知正确的前提下，选对下一步了吗（子目标、失败恢复、状态覆盖） | 数据分布补洞（恢复演示）、chunk 设计 |
| 控制 | 决定正确的前提下，做得到吗（精度、力度、时序） | 动作头容量、数据侧精细操作演示、控制频率 |

⚠️ SmolVLA 是端到端模型，**没有显式的三层模块边界**——三层是功能透镜，不是代码模块。定层结论的含义是「干预哪个环节能救活」，指导修复方向（数据/训练/接口），不是指认某段网络。

## 预注册实验（R → F → T）

### Exp R：重放保真——已对账（2026-07-27）

> 🧭 **2026-08-06 更新框**：本节（及 Exp F）中「init3 = 0/13 毒布局实锤 / 硬零档离群点」的**难度定标**后来被推翻——该硬零是 MuJoCo 3.8.1 打破 task5 落座前提的版本伪影（8/06 同探针协议 @3.2.7 复测：SmolVLA **9/10**）。本节的可复现性结论（聚合稳定/逐集非确定）与「布局决定难度档位」的档位结构不受影响，但档位表是 3.8.1 坏前提物理下的档位。全案见 leaderboard v2「版本敏感度」节。

同命令、同 seed(1000)、同 checkpoint 重跑 30k 官方评测 100 集（输出 `smolvla_spatial_b64_30k_ckpt030000_n1_replay20260727`）。**已知环境差异**：原跑（7/20）在旧 conda venv（torch 2.11.0+cu126、`TORCHDYNAMO_DISABLE=1` eager），本跑在 uv venv（cu130、compile 生效）——两处数值差在闭环里混沌放大。

判据分四级：L1 总成功率 → L2 逐任务分布 → L3 逐集网格全同 → L4 逐帧。
**Claude 预注册**：L1/L2 守住，L3 大概率不全同。
⚠️ 判读纪律：R 中 ep3 是否复现死机**不裁决**「单次事故 vs 系统模式」——裁决交给 F。

**结果：L1 ✓（84.0 vs 82.0，差 2 集，CI ±7.5pp 内）；L2 ✓（task5 两跑同为全场最差 2/10，其余任务 8–10/10 形状一致）；L3 ✗（逐集一致 84/100，16 集翻面）——与预注册方向一致。**

- 翻面集中在弱任务：task5 翻 4、task8 翻 4、task9 翻 3；强任务（task0/2）100% 一致。符合「成功率居中的 episode 对数值扰动最敏感、双峰任务稳定」的混沌+随机预期。
- task5 内部翻面方式本身是证据：原跑成功 = ep6/8，重放成功 = **ep1/5**（完全换人）——**布局决定难度档位、噪声在档位内掷骰**。ep5 原跑「双碗同抓整摞判负」布局这次成功，ep3 布局两跑皆败（并 Exp F 累计 **0/12**）。
- task5 分布局战绩（跨 orig/replay/F/smoke 全部噪声抽样）：init3 = 0/12（毒布局实锤）；init6 = 2/3；init1/5/8 = 1/2；init0/2/4/7/9 = 0/2。
- **对外措辞落定**：harness 可复现性声明 = 「聚合指标跨环境可复现（82→84）；逐集复现仅在同一软件栈内成立（待 replay-B 定谳）」。7/24 标注定谳的**模式级结论**不受影响（F 已在模式级复证 H1=0、抓取/放置主导）。

**replay-B 定谳（当日）**：栈内同命令同 seed 二连跑，A vs B 逐集一致 **84/100**（总分同为 84.0）——**逐集非确定性是本栈固有属性，与跨栈环境差异无关**（上文把 L3 失败归因于 cu126→cu130 + compile 的推测被证伪，自纠）。嫌疑源：eval 显式开 `cudnn.benchmark=True`（按实测计时选算法，本身不确定）+ compile autotune + GPU 原子操作规约序，闭环混沌放大。三跑总分 82/84/84——聚合指标磐石级稳定。

**最终措辞**：可复现性 = 聚合指标级（多次重跑落在二项噪声带内）；**逐集身份即使同栈同 seed 也不保证**。若未来需要逐集确定，走 `torch.use_deterministic_algorithms` + 关 benchmark 的 `--deterministic` 模式（有性能代价，列为 harness 待办，暂不做）。方法论推论：**任何逐集级归因必须建立在多噪声抽样上**（如 Exp F 的 ×10）——本框架的多 seed 方法不是可选项，是必需品；单次 n=1×100 的逐集成败表本身就是一次噪声抽样。

**task5 分布局战绩更新（并入 B）**：init3 = **0/13**（毒布局结论加固）；init6 = 3/4；init8 = 2/3；init1/5/7 = 1/3；init0/2/4/9 = 0/3。除 init3 外多数布局呈中概率掷骰（task5 三次全量跑合计 7/30 ≈ 23%），「布局分档」精确表述为：init3 是硬零档离群点，其余布局在 0–75% 区间内随噪声波动。

### Exp G：抓取偏心假说与离线几何测量（7/27，Rick 看片提出 → 当日数值证实）

> 🧭 **2026-08-06 更新框**：本节及 Exp T/T-3/V 的因果链（布局→抓取侧→在手偏心→落点→谓词，Fisher p≈0.0098）全部建立在 3.8.1 物理内、对照对称，**栈内有效性不变**。但要害重定性：3.8.1 下 init3 的碗**开局已滑脱、以异常角度斜靠 ramekin**（8/05 抽帧定谳）——「摆位诱导左缘抓取”的上游很可能正是这个被破坏的碗姿，而非布局坐标本身；健康物理（碗正坐）下 init3 命中 9/10，左缘诱导现象大概率不复存在。因此本链是「坏前提物理下的失败机制解剖」，对「LIBERO task5 本身」的外推须加版本前提。

**假说（Rick，重看 task5 视频归纳）**：抓取落在碗缘的哪一侧由初始布局决定；策略放置时以爪为参照、不补偿碗在爪中的偏心 → 抓偏侧 = 落点偏移 = 谓词（<3cm）不亮。
**测量工具**：`scripts/grasp_offset_analysis.py`（读状态 dump，纯离线零 GPU 成本）。轴标定：+y=画面左（柜 y=−0.264 在画面右锚定），−x=远端/基座方向。

三项测量结果（数据源：Exp F 十局 + smoke 成功局的状态 dump）：
1. **布局间只差厘米级，敏感度却是 0% vs 75%**：50 个 init 摆法中目标碗位波动仅 ±1.5cm，init3 位置不离群——但 bowl−plate 的 y 分量 init3 最负（−1.25cm）而战绩最好的 init6/init8 恰为最正（+2.5/+1.05cm）。厘米级摆位差翻转抓取侧的机制待查（疑与训练分布位置先验有关）。
2. **抓取侧二分法证实（Rick 原表述方向正确，未说反）**：smoke 成功局爪握碗**右缘**（bowl−eef=(+0.003,+0.043)）；F 四局抓稳全部握**左近缘**（bowl−eef≈(−0.02~−0.04, −0.01~−0.03)），4/4 同侧。
3. **无补偿实锤**：四局落点全部「已在盘上（z +1cm）、离盘心 4.4–5.5cm」——只差 1.4–2.5cm 亮灯；抓取偏移的 x 分量近 1:1 带到落点（−4.3→−3.9、−1.7→−1.4、−3.1→−3.1、−1.8→−3.5cm）；落点偏差 ≈（实际抓取方向 − 常规抓取方向），方向逐局吻合。碗缘握持天然偏心 ~4.3cm > 谓词半径 3cm → **抓错侧就出局，不存在带偏心的成功放置**。

**含义**：①H2b 与 H3 从两类现象合并为一条因果链；②毒布局机制候选解=「init3 的摆位诱导左缘抓取」；③修复方向指向数据侧（抓取侧多样性/重定位演示），推理侧无旋钮（与 7/24「看见了也不会改」咬合）；④Exp T 从探索性升级为**验证性**。

- **故障定谳（状态 dump 逐步测量）**：碗在接管后 2–4 步内**掉落**（z 1.06→0.93，13/13），随后空爪游走/去盘区按压（稀疏帧曾两次误读为「持碗运输」，全视频/数值复核推翻）。根因链：`MjSim.get_state()` **不含执行器 ctrl**——①reset 后夹爪 ctrl 从「张开」增量爬行，闭合指令追不上（v2 闭合空动作沉降仍掉）；②把 ctrl 钉在手指当前位置 = 位置误差为零 = **零夹持力**，摩擦扛不住重力（v3 仍掉）；③正解 = rollout 采集时**逐步 dump 完整 ctrl 向量**，注入时原样恢复（探针 v4 已实现，注入源带 ctrl 重采中）。
